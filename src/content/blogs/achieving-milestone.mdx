# Building SRTSync: Turning Subtitle Timing Into a Better Workflow

I built SRTSync to make subtitle timing work feel less frustrating. The goal was simple: give people a clear way to shift, stretch, validate, preview, and download SRT files from one focused interface.

## The Problem

Subtitle timing is easy to get slightly wrong and surprisingly tedious to fix by hand. A small offset can affect an entire file, while FPS changes can create drift across a video. I wanted the workflow to make those operations visible and reversible.

## What I Built

- A React interface for shifting subtitle timestamps.
- FPS stretching for adapting subtitles to a different video frame rate.
- Validation feedback for malformed or overlapping subtitle entries.
- Live preview, undo/reset controls, and instant SRT export.

## What I Learned

The most useful part of the project was learning to keep complex state understandable. Every edit needs to be predictable, and every destructive-looking action should be easy to undo. That pushed me toward reusable components, explicit time utilities, and validation close to the editing experience.

## Next Steps

I want to keep improving the editor with stronger accessibility, more import/export options, and clearer feedback for edge cases. SRTSync is also a good example of the kind of practical, user-focused software I want to keep building.
